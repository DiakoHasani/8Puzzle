# 8 Puzzle — حل معمای ۸ (جدول ۳×۳) با چند الگوریتم جستجو

برنامه‌ای ویندوزی (Windows Forms) برای **نمایش گرافیکی** حل معمای ۸ است. در این بازی، جدول ۳×۳ یک خانهٔ خالی (`0`) و هشت کاشی شمارهٔ ۱ تا ۸ دارد. هدف رسیدن به چینش نهایی با جابه‌جا کردن خانهٔ خالی است:

```
0 1 2
3 4 5
6 7 8
```

هر الگوریتم در یک فرم جدا پیاده‌سازی شده و مسیر رسیدن به جواب را **قدم‌به‌قدم روی جدول انیمیت** می‌کند. این پروژه برای یادگیری و مقایسهٔ الگوریتم‌های جستجوی هوش مصنوعی مناسب است.

## الگوریتم‌های پیاده‌سازی‌شده

| الگوریتم | توضیح |
|----------|-------|
| **A\*** | جستجوی آگاهانه با تابع هزینهٔ `عمق + فاصلهٔ منهتن`، با صف اولویت (IntervalHeap) |
| **BFS** | جستجوی سطحی با صف اولویت. هزینهٔ هر گره تعداد کاشی‌های جابه‌جا، به‌علاوهٔ لگاریتم عمق است. |
| **IDS** | جستجوی عمقی با افزایش تدریجی عمق (Iterative Deepening Search) |
| **Accidental** | حرکت تصادفی تا رسیدن اتفاقی به جواب، به‌عنوان مبنای مقایسه |

## ویژگی‌ها

- رابط گرافیکی با فرم جدا برای هر الگوریتم
- انیمیشن حرکت کاشی‌ها و رنگ‌بندی خانه‌ها
- نمایش آمار اجرا (مثل عمق جواب، تعداد گام‌ها و تعداد گره‌های تولیدشده)
- حالت انیمیشنی و غیرانیمیشنی برای الگوریتم تصادفی
- معماری ساده بر پایهٔ اینترفیس (`IAStar`، `IBfs`، `IIds`، `IAccidental`، `IPrintService`) که منطق الگوریتم را از نمایش جدا می‌کند

## ساختار پروژه

```
8Puzzle/
├── Core/            # اینترفیس‌ها (الگوریتم‌ها، چاپ جدول، صف اولویت)
├── Enums/           # Move و State
├── Forms/           # FrmMain، FrmAStar، FrmBFS، FrmIds، FrmAccidental
├── Infrastructure/  # پیاده‌سازی الگوریتم‌ها (AStar، Bfs، Ids، Accidental) و صف اولویت
├── Models/          # Board، State (شامل محاسبهٔ فاصلهٔ منهتن)، Result
└── Program.cs
```

- C# · .NET Framework 4.6.2

## پیش‌نیازها

- Windows
- Visual Studio 2019/2022 با پشتیبانی از .NET Framework 4.6.2

## اجرا

```bash
git clone https://github.com/DiakoHasani/8Puzzle.git
```

۱. فایل `8Puzzle.sln` را در Visual Studio باز کنید.
۲. بسته‌های NuGet را بازیابی کنید.
۳. با `F5` اجرا کنید.
۴. در فرم اصلی الگوریتم دلخواه را انتخاب کنید و دکمهٔ شروع را بزنید.

## نکات

- چینش اولیه در کد هر فرم تعریف شده است (مثلاً در `FrmBFS`: `{3,8,1},{6,2,5},{0,4,7}`). برای تغییرش باید کد را عوض کنید.
- الگوریتم **Accidental** تصادفی است. زمان رسیدنش به جواب قابل پیش‌بینی نیست و ممکن است طولانی شود.
- IDS برای چینش‌های عمیق و دشوار ممکن است کند باشد.
- همهٔ چینش‌های دلخواه قابل حل نیستند. فقط نیمی از جایگشت‌های ممکن به هدف می‌رسند.
